The problem

Moving data off a system people still rely on means running the old and the new side by side for a while. Every change on the source has to reach the target, and at any point you need to be able to show the two still agree.

How it works

Change data capture on the SQL Server source records each insert, update and delete as it happens. Those changes flow into the lakehouse, so it keeps up with the source without anyone switching the source off.

How I prove it's right

A reconciliation report compares the source and the lakehouse and shows whether they match.
